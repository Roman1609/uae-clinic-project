# Інструкція: Архітектура кінематографічної Hero-секції (Desktop Scrub vs Mobile Horizontal Slider)

> Цей документ створено як еталонний стандарт і технічне керівництво для розробників та ШІ-агентів при створенні інтерактивних сайтів із покадровою canvas-анімацією (3D/відео-рендери).

---

## 1. Головна концепція та архітектурне правило

### ⚠️ Головне правило мобільного UX:
> **НІКОЛИ НЕ ЗАХОПЛЮЙТЕ ВЕРТИКАЛЬНИЙ СКРОЛ НА МОБІЛЬНИХ ПРИСТРОЯХ!**
> Спроба перехоплювати жести `touchmove` вгору/вниз або блокувати `document.body.overflow = "hidden"` для внутрішніх слайдів завжди призводить до конфлікту з апаратним потоком композитора мобільного браузера (iOS Safari / Android Chrome), ривків, застрягання користувача та блокування жесту оновлення сторінки (pull-to-refresh).

### 🖥️ На комп'ютерах (Desktop, екран >= 1024px):
- **Покадровий вертикальний скрол (Scroll Scrub)**.
- Контейнер має висоту `h-[480vh]`.
- Sticky-вікно фіксується у вьюпорті (`sticky top-0 h-[100dvh]`).
- Прокрутка коліщатка миші переміщує поточний прогрес від кадру 0 до кадру N за допомогою математичної інтерполяції (Lerp) на 60fps.

### 📱 На смартфонах та планшетах (Mobile & Tablet, < 1024px або Touch-пристрої):
- **Горизонтальний преміум-слайдер із фоновою анімацією (Horizontal Slider + 60fps Frame Playback)**.
- Контейнер займає рівно висоту одного екрана `min-h-[100dvh] h-[100dvh]`.
- **Вертикальна вісь повністю вільна (`touch-action: pan-y`)**: користувач може будь-якої миті вільно скролити сторінку вниз до наступних блоків або потягнути вниз для оновлення.
- **Горизонтальна вісь перемикає слайди**:
  1. Свайп пальцем вліво/вправо (`diffX > 35px`).
  2. Плаваючі напівпрозорі стрілочки `‹` та `›` під великий палець.
  3. Клікабельні таби фаз внизу (`01 Advisory`, `02 Licensing`, `03 Metrics`, `04 Launch`).
- **При перемиканні слайду** запускається плавна функція `animateToStage(target)`, яка покадрово програє відео на фоновому canvas на 60fps у потрібному напрямку!

## 2. Параметри швидкості та налаштування в коді

У файлі `src/components/HeroScrollCanvas.tsx` на самому початку винесено об'єкт конфігурації `HERO_ANIMATION_CONFIG`:

```tsx
export const HERO_ANIMATION_CONFIG = {
  /**
   * Плавність / швидкість реакції десктопного скролу (від 0.01 до 1.0)
   * Чим БІЛЬШЕ значення (напр. 0.45) — тим РІЗКІШЕ та швидше змінюються кадри.
   * Чим МЕНШЕ значення (напр. 0.12) — тим ПЛАВНІША та важча кінематографічна інерція.
   * Оптимально: 0.25 (шовковисті 60fps).
   */
  desktopLerpSpeed: 0.25,

  /**
   * Мінімальна тривалість переходу між сусідніми слайдами на мобільному (в мілісекундах).
   * Оптимально: 650ms.
   */
  mobileMinDurationMs: 650,

  /**
   * Максимальна тривалість переходу через кілька слайдів на мобільному (в мілісекундах).
   * Оптимально: 1200ms.
   */
  mobileMaxDurationMs: 1200,

  /**
   * Коефіцієнт масштабування тривалості анімації від кількості проміжних кадрів.
   * Оптимально: 1500.
   */
  mobileDurationScale: 1500,

  /**
   * Поріг чутливості горизонтального свайпу на тач-скріні (в пікселях).
   * Скільки пікселів треба протягнути палець для зарахування свайпу.
   * Оптимально: 35px.
   */
  mobileSwipeThresholdPx: 35,

  /**
   * Загальна висота секції для десктопу у vh (довжина прокрутки миші).
   * Чим більше — тим повільніше змінюються кадри при звичайному скролі.
   * Оптимально: 480vh.
   */
  desktopScrollHeightVh: 480,
};
```

Ці параметри можна також передавати через `props` компонента:
```tsx
<HeroScrollCanvas
  totalFrames={196}
  desktopLerpSpeed={0.3}
  mobileMinDurationMs={500}
  mobileMaxDurationMs={1000}
/>
```

## 3. Оптимізація зображень (WebP конвертація)

Для плавного рендерингу 150–200 кадрів без перевантаження оперативної пам'яті смартфонів:
1. Вихідні файли JPG або PNG конвертуються у формат `.webp` із якістю `75–80`.
2. Розмір зменшується у 3–5 разів (з 40 МБ до 7–10 МБ на весь набір).
3. Скрипт автоматичної конвертації: `scripts/convert_all_to_webp.mjs`.

Приклад виклику в терміналі:
```bash
node scripts/convert_all_to_webp.mjs
```

## 4. Промпт-шаблон для ШІ-агента для майбутніх проєктів

Скопіюйте текст нижче та надішліть ШІ-агенту, коли потрібно реалізувати подібну секцію з нуля:

```text
Потрібно створити інтерактивну Hero-секцію з покадровою Canvas-анімацією (sequence з N кадрів у форматі WebP):

1. ДЕСКТОП (екран >= 1024px):
   - Реалізуй вертикальний покадровий скрол (Scroll Scrub).
   - Загальна висота контейнера: h-[480vh], sticky-контейнер h-[100dvh].
   - Розраховуй поточний кадр через прогрес скролу та згладжуй рух за допомогою Lerp (лінійна інтерполяція: current += (target - current) * lerpSpeed) на requestAnimationFrame.

2. МОБІЛЬНІ ТА ПЛАНШЕТИ (< 1024px або touch):
   - КАТЕГОРИЧНО НЕ блокуй вертикальний скрол сторінки (ніякого overflow: hidden на body, ніякого touch-action: none, ніякого preventDefault на vertical touchmove).
   - Встанови на контейнер touch-action: pan-y, щоб вертикальний скрол сайту та жест pull-to-refresh працювали на 100% природно.
   - Зроби Hero-секцію горизонтальним слайдером:
     a) Перемикання фаз через горизонтальний свайп пальцем вліво/вправо (diffX > 35px).
     b) Додай плаваючі напівпрозорі стрілочки перемикання ‹ та › по боках під великий палець.
     c) Додай клікабельні індикатори фаз внизу.
   - При зміні слайду плавно програвай відповідні проміжні кадри фонового canvas на 60fps за допомогою requestAnimationFrame та cubic-bezier easing.

3. НАЛАШТУВАННЯ ШВИДКОСТІ:
   - Винеси об'єкт HERO_ANIMATION_CONFIG на самий початок файлу компонента (desktopLerpSpeed, mobileMinDurationMs, mobileMaxDurationMs, mobileSwipeThresholdPx), щоб параметри можна було легко змінювати.
```
